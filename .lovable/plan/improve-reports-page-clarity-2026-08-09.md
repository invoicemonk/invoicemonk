# Improve Reports Page Clarity

## Goal
Make the Reports section immediately understandable for both business owners and accountants on InvoiceMonk, while keeping the existing category-based layout and download/email flow intact.

## What users need this page to do
1. **Business owner insight**: Quickly see which invoices are unpaid, which clients bring in revenue, how expenses break down, and whether cash is flowing in or out.
2. **Formal accounting/tax export**: Download compliant CSV/PDF files to hand to an accountant or tax authority with clear labels, dates, and verification hashes.

## Current pain points
- Report titles are mostly bookkeeping/accounting jargon (e.g., "Invoice Register", "Audit Export").
- No preview of what columns, totals, or sample rows the downloaded file will contain.
- No guidance on which report to use for which job (tax filing, client review, accountant hand-off).
- Currency-account scoping is hidden behind a small badge; users may not realize why a report is empty.
- The "Reports vs Analytics" switch is unexplained.
- Tier-locked reports are dimmed but not explained; users only see a tier badge.

## Proposed changes

### 1. Rewrite every card with plain-language labels
- Keep the report ID and underlying functionality unchanged.
- Add a human-readable tagline next to each title, e.g.:
  - *Invoice Register* → "Every invoice you sent this year, with payment status."
  - *Outstanding Report* → "Who owes you money and how late it is."
  - *Tax Report* → "Tax collected and credit-note adjustments for filing."
- Display the existing description in a smaller, secondary line.

### 2. Add a use-case chip on each card
Add a small badge showing the primary use case:
- **Tax / Filing** (Tax Report, Audit Export)
- **Accountant** (Invoice Register, Income Statement, Cash Flow Summary)
- **Business review** (Revenue by Client, Outstanding Report, Expenses by Category)
- **Compliance proof** (Audit Export, Export History)

### 3. Inline preview panel before downloading
- When a user clicks a report card, expand the card in place and show:
  - A sample of the first 3-5 rows of data (generated by the existing `generate-report` function in `json` format).
  - A list of the key columns/totals the report will include.
  - The total row count and currency.
- Provide **Download CSV / PDF / JSON** and **Email** buttons from the preview, not from the main card.
- This prevents the user from downloading a file blindly and then realizing it is the wrong one.

### 4. Empty-state guidance per report
- If a report has no data for the selected year and currency account, show a clear message instead of an empty CSV.
- Example: "No expenses recorded in this currency account for 2026. Add expenses to generate this report."
- Link to the relevant entry point (e.g., New Invoice, New Expense, Receipt Upload).

### 5. Clarify currency-account scoping
- Move the currency account notice to the top and make it an action banner.
- If no currency account is selected, show a single prominent "Select a currency account" prompt and disable financial reports with a tooltip explaining why.
- When a currency account is selected, show the account name, currency, and current-year balance if available.

### 6. Add a short Reports Guide section
- Add a small collapsible "How to use these reports" help block at the top of the Reports tab.
- It explains:
  - Reports are scoped to one currency account (InvoiceMonk never mixes currencies).
  - CSV is for Excel/Google Sheets; PDF is for sharing/filing; JSON is for integrations.
  - Analytics shows charts; Reports downloads data.

### 7. Improve locked-state messaging
- Instead of just dimming the card and showing a tier badge, show a short sentence:
  - "This report requires the Professional plan." or "Tax reports require the Business plan."
- Keep the "Upgrade" prompt behavior unchanged, but add a clickable upgrade action inside the card when locked.

### 8. Keep tabs, year selector, and email dialog unchanged
- The existing category tabs, year selector, Reports/Analytics tabs, and `EmailReportDialog` remain.
- Only the report cards and their preview behavior are reworked.

## Files to edit
- `src/pages/app/Reports.tsx` — main layout, card expansion, preview, and guide.
- `src/hooks/use-reports.ts` — reuse `generateReport` for previews; add a lightweight `useReportPreview` hook.
- `src/components/reports/ReportPreviewCard.tsx` — new component for expanded report previews.
- `src/components/reports/ReportGuide.tsx` — new collapsible help panel.
- `src/components/reports/ReportUseCaseBadge.tsx` — small badge mapping report IDs to use cases.

## Out of scope
- No changes to the backend `generate-report` edge function or data model.
- No changes to the Analytics tab content.
- No new report types or exports formats.
- No subscription/tier changes.

## Success criteria
- A user can glance at a report card and know what it is for.
- A user can preview the data before downloading.
- A user with no data gets a clear next step instead of an empty file.
- A user understands why reports are tied to a currency account.
